# Motorcycle Use Notes

このロガーは汎用の GPS / IMU 測定プログラムですが、想定している用途はバイクです。ここでは用途の目的、実データで分かったこと、判定の設計メモ、未決事項を残します。実装済みの仕様ではなく、設計の検討記録です。

## 想定する用途

1. **オートウィンカーオフ**: ウィンカーの切り忘れ防止。交差点を曲がったことを、速度・加速度・角速度から判定してオフ信号を出す
2. **サーキット走行の分析**: バンク角、ブレーキ時の前後 G、コーナーごとの最小速度、ラップタイムなど

English supplement: The logger is general-purpose; motorcycle use cases (auto turn-signal cancel, circuit analysis) drive these notes. This is a design memo, not shipped behavior.

## ログの扱い

- 正本は `sensor_*.bin`。CSV と HTML は派生データです ([Sensor Log Format](sensor_log_format.md))
- 実機ログの IMU は `*_imu_batch.csv` に入ります(`*_imu.csv` は 0 行)
- `imu_batch` は 10 サンプル(100 ms)単位で、生サンプルに加えて `summary_*`(加速度 3 軸・角速度 3 軸の avg / min / max)を持ちます
- 解析は「間引いてから見る」のではなく、特徴量を作ってから間引きます。平均だけの間引きは短いピークを消すので、グラフには `summary_*` の avg 線と min〜max の帯が向いています
- 角度の積分には avg でも十分です(avg × 0.1 s が角度の増分に近い)。ロール推定は加減速で重力方向がずれるため、100 Hz の生サンプルのほうが安定します
- 推奨する層: 生(100 Hz、正本)→ 特徴量(10 Hz: ロール角、ヨーレート、ヨー角累積、前後・横 G、速度、min/max)→ イベント(曲がり、ブレーキ区間、コーナー区間)

## 実データでの確認(車のダッシュボードに水平固定)

バイクに載せる前の動作確認として、車のダッシュボードに置いたまま実走行(約 2.8 時間、停車中が約 84%)を記録しました。

- 静止時の重力は z 軸にほぼ一致し、水平に固定できていました。ジャイロの零点は z 軸で約 -0.24 deg/s ずれており、停車中の平均を引けば補正できます
- ジャイロのヨー積分は、GPS の進行方向の変化と、大きな曲がりで概ね 5〜15% 以内で一致しました。符号は逆なので合わせが要ります
- `scripts/plot_sensor_csv.py` に曲がり検出を入れ、GPS 地図に曲がり区間のマーカー(橙=右折、紫=左折)を出せます。IMU 由来の判定で、往復の同じ交差点に対になる曲がりが出ており、概ね妥当でした
- 速度ゲート(時速 10.8 km 超)があるため、狭い道を徐行した交差点は落ちることがあります
- IMU に欠損(0.5 秒超の穴)はありませんでした

English supplement: Test data was recorded in a car with the unit lying flat; heading integrated from gyro matched GPS course change within roughly 5–15% on large turns.

## バイクでの注意点

- **ロール**: バイクは傾くので、機体座標の gz をそのまま積分してもヨーになりません。重力方向(ロール角)を推定して、重力軸まわりの成分に変換します。ロール角は加速度とジャイロの相補フィルタで推定します。車載の検出コードは水平固定が前提で、そのままでは使えません
- **取り付け向き**: 機体の軸とバイクの軸の対応が必要です。静止時の重力方向と、直進加速時の方向から自動で求められます
- **ジャイロ零点**: 停車中(GPS 速度 ≈ 0)の平均で補正します。GPS が使えない場面に備えて、加速度の分散が小さい状態が続いたら静止とみなす判定も検討します
- **GPS の更新間隔**: 現状約 1 Hz。時速 150 km で 1 点が約 40 m 進むため、サーキットの走行ラインには粗いです。10 Hz にできるかは GPS モジュール側の設定を確認します

## オートウィンカーオフの設計メモ

目的は切り忘れ防止なので、検出動作はウィンカーが ON であることが前提です。速度ゲートは、ウィンカー状態が分からないときの誤検出対策なので、ウィンカー ON のあいだは外すか、ごく低い値(時速 1〜2 km 程度)にします。

ウィンカー ON のあいだ、次のどれかを満たしたら OFF 信号を出します。

1. **曲がり終わり**: ON 以降のヨー角の累積が、ウィンカーの向きに 45〜60° を超え、その後ヨーレートが小さくなって直進に戻った
2. **時間切れ**: 速度がある間だけ進むタイマーが一定時間(例: 30 秒)を超えた。停車中は止めるので、長い信号待ちでは消えない
3. **加速**: 一定の速度(例: 時速 40 km)を超えて、数秒続いた。曲がりも車線変更も終わったと見なす

設計上の注意:

- ヨー角の累積は、ウィンカー ON の瞬間に 0 にします。ON の数秒前までさかのぼる余地は残します
- ウィンカーと逆向きの曲がりは累積に入れません(切り返しでの誤オフ防止)
- ハザード(左右同時点灯)は対象外です
- 車線変更はヨー角が小さいので、1 ではなく 2 か 3 で消えます
- 停車後に再発進したときの扱い(再発進から一定時間、または再発進後の最初の曲がりで消す、など)は未決です

English supplement: Cancel only while the signal is on; cancel on (1) completed turn in the signal's direction, (2) a moving-time timeout (paused while stopped), or (3) sustained speed above a threshold. Ignore opposite-direction yaw and hazard state.

## 未決・次にやること

- ウィンカー状態がログに入っていません。検証用に、ウィンカー信号の ON/OFF(左右)をログへ足す必要があります(GPIO 入力、ESP-NOW パケットなど、取り方は実機側の設計)
- ウィンカーのログが揃うまでは、検出済みの曲がりの数秒前にウィンカー ON を仮定して、OFF 信号が出るタイミングを見るシミュレーションが使えます
- 曲がり検出にロール補正を入れ、バイクで再確認する
- ダッシュボードを `summary_*` の avg 線 + min〜max 帯にして、生サンプルの展開を不要にする
- サーキット向けに、バンク角・前後 G・コーナー検出などの特徴量を足す
- GPS の 10 Hz 化の可否を確認する
